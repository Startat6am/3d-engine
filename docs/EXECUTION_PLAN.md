Local Node 25.9.0 checks pass (99/99 workspace tests, typecheck, ESLint, Editor/Player builds, changed-file formatting); supported Node 22 CI and Chromium E2E are pending.

- PR #65 ([worker-backed GLB import](https://github.com/Startat6am/3d-engine/pull/65), branch `feat/worker-backed-glb-import`) is stacked on PR #64. GLB parsing, meshopt decode, geometry construction, and image extraction now run in a dedicated Vite module worker. Source and imported typed-array buffers are transferred rather than cloned; the original source buffer is transferred back before resolution so Editor can persist the exact GLB payload. The worker is terminated on success, cancellation, worker failure, or unreadable messages. Unit tests cover transfer/restore, pre-abort, in-flight cancellation, importer failure, and messageerror; browser E2E confirms a worker is created/terminated and `.world` payload bytes remain intact. CI #207 passed on Node 22: 95/95 unit tests, Editor/Player builds, both 128 MiB peak-RSS stress budgets, and 16/16 Chromium E2E tests. This completes the GLB worker-import gate; browser/GPU memory ceiling, renderer shutdown GPU teardown E2E, and binary project asset store remain open. No PRs have been merged.

- PR [#69](https://github.com/Startat6am/3d-engine/pull/69) records the accepted directory-project asset storage decision in ADR-0002. `.world` remains a JSON manifest; directory projects store immutable content-addressed blobs under `assets/sha256/`, while optional Base64 `assetPayloads` remain supported for portable single-file snapshots. Save writes/verifies blobs before the manifest; open validates safe project-relative URIs and hashes before committing scene state. This is an architecture decision only; the storage adapter and Editor directory workflow remain open implementation gates.
